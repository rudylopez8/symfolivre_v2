Contexte du Projet

Origine du besoin

Inspiration issue du service EOLE (Association Valentin Haüy) : fournir des livres adaptés aux personnes en situation de handicap visuel ou moteur.

L'objectif est de créer une plateforme généraliste permettant la diffusion d'ouvrages en formats Texte (.txt, .md) et Audio (.zip/mp3).

Modalités de réalisation

Projet réalisé en autonomie suite à un stage chez [BAM] (propriété intellectuelle restreinte).

Démarche visant à démontrer l'intégralité des compétences du référentiel CDA : de l'analyse au déploiement.

Architecture Logicielle BC01 / BC02

L'application suit l'architecture MVC (Modèle-Vue-Contrôleur) native à Symfony :

Modèle (Entity/Repository)
Accès aux données via Doctrine ORM.
Contrôleur
Logique métier et routage des requêtes.
Vue (Twig)
Interface utilisateur dynamique et responsive.
Sécurité appliquée :
  • Firewall Symfony : Gestion des sessions et authentification.
  • Access Control : Restriction des routes par rôles (ROLE_USER, ROLE_AUTEUR, ROLE_ADMIN).
  • Validation : Protection CSRF sur tous les formulaires de suppression.

Développement & Métier BC01

Fonctionnalités Clés Implémentées

  • Gestion des fichiers : Système de stockage sécurisé dans /uploads avec noms de fichiers uniques.
  • Moteur de recherche : Requêtes personnalisées dans le BookRepository (LIKE pour titre, '=' pour ISBN).
  • API REST : Endpoint JSON pour l'interrogation externe des ouvrages.

Défis Techniques

Gestion des types : Distinction stricte entre lecture en ligne (.txt/.md) et téléchargement obligatoire pour l'audio (.zip).
Intégrité : Interdiction de supprimer un auteur possédant encore des livres (Contrainte FK).

Déploiement & DevOps BC03

Procédure de Mise en Production

  1. Configuration du serveur (PHP 8.2, MariaDB, Apache/Nginx).
  2. Installation des dépendances via composer install --no-dev.
  3. Migration de la base de données : doctrine:migrations:migrate.
  4. Optimisation du cache Symfony.

Maintenance & Veille
